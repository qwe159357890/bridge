## 一、需求一句话

在 Bridge 安卓 APP「主页」之后新增一个「监控」入口，原生（Kotlin + Compose）重新实现 NVR 8200 统一控制台的**部分**功能，UI 与管理后台完全独立设计，只借鉴参考项目的数据链路与同类 APP（大华云联/萤石云）的交互范式。

**本期实现四大功能**：①实时预览 ②事件 ③云端 ④延时摄影。

**明确不做**：直接套用 Web（不内嵌 WebView 加载 8200 页面）、录像段台账页（Segments）、看板（Dashboard）、多节点管理（node 增删）、上传队列、网盘登录。

## 二、背景与现状（为什么能做成）

### 2.1 Bridge APP 与 NVR 已是同一套组网体系

| 事实 | 证据 |
|------|------|
| 两端都已升级 VNT 2.0 | Bridge v0.2.131 完成 1.x→2.x；NVR 全量机器 2026-11-13 升级 vnts2@31008 |
| 虚拟网段一致 | `86.74.128.0/24`，APP 设备与 NVR 节点可互通 |
| NVR hub 8200 地址 | 盒子2（wxy2）`86.74.128.68:8100`（节点）+ `8200`（hub 统一控制台） |
| 鉴权 | hub 有 `HUB_API_TOKEN`；节点 8100 有 `API_TOKEN` |

**关键结论**：APP 无需再建任何隧道/转发，只要设备端 VNT 组网在线，即可直接通过 VNT 虚拟网访问 NVR 节点（8100）或 hub（8200）的 HTTP API。实时预览与点播本质是「APP 拉 HTTP 媒体流」。

### 2.2 NVR 现有能力盘点（参考项目已实现，APP 直接消费其 API）

| 能力 | 参考实现 | APP 是否需要 |
|------|---------|-------------|
| 实时预览 | MJPEG 子码流 / fMP4 音视频流 / HTTP 快照 | ✅ 核心 |
| 事件流 | 事件监听 → SQLite → `/api/events`（human/motion 分级 + 快照） | ✅ 核心 |
| 云端录像 | 天翼+百度双盘 → `/api/cloud/list` + `/api/video/*` 点播 | ✅ 核心 |
| 延时摄影 | 定时快照 → 日合成 → 双盘 → `/api/timelapse/*` | ✅ 核心 |
| 录像段台账 | `/api/segments`（未销账段） | ❌ 本期不做 |
| 看板 | `/api/status`（今日段统计/容量） | ❌ 本期不做 |
| 多节点聚合 | hub `/api/hub/*` + `/<节点>/<path>` 代理 | ✅ 本期做（见 §5） |

## 三、同类 APP 调研（UI 与交互范式）

### 3.1 大华云联（大华系，与参考摄像头同源）

- **首页**：模块化卡片列表，一设备一张卡（缩略图 + 名称 + 状态点）。
- **实时预览**：点卡片即进直播（2~3 秒出画面）；支持**流畅/高清多档画质切换**（网络差自动降码流）；双指缩放、截图、对讲、云台控制（本项目无云台）。
- **回放**：预览页底部「回放」→ 日历选日期 → **蓝色时间轴高亮有录像时段** → 拖拽定位 + 倍速/逐帧。
- **报警**：移动侦测→推送 + 图片预览，点开看**报警截图 + 关联录像**。

### 3.2 萤石云视频（海康系）

- **首页**：缩略图墙（宫格），点缩略图进现场视频。
- **多画面**：1/4/9/16 宫格分屏，多路同时看。
- **画质**：流畅/均衡/高清三档。
- **回放**：下方时间轴拖拽 + 日期切换 + 刻度（分/时/天）切换。
- **手势**：单指拖云台、双指缩放、双击放大、左右滑动切设备。

### 3.3 提炼出的共性范式（APP 原生 UI 的骨架）

| 范式 | 说明 |
|------|------|
| **一页一 Tab，卡片/宫格打底** | 首屏就是内容（摄像头卡片墙/事件列表），不设空看板 |
| **「点进即播」** | 缩略图 → 全屏直播，不是「列表→详情→再点播放」多层跳转 |
| **快照/实时双档带宽治理** | 列表页默认静态快照（省流量），点开才拉实时流 |
| **画质档位** | 流畅(子码流)/高清(主码流) 显式切换，公网默认流畅 |
| **事件=缩略图 + 关联录像** | 报警消息带快照缩略图，点开能看快照也能跳录像 |
| **回放按「日期 → 时间轴」** | 日历选日期，时间轴标有录像段，拖拽定位 |
| **状态点三色** | 绿=在线、灰=离线、转圈=连接中 |

## 四、功能设计与原生实现方案

### 4.0 总体结构

```
监控（新增底部 Tab，插在「主页」之后，第 2 位）
 ├─ 实时预览（默认落地页）
 ├─ 事件
 ├─ 云端
 └─ 延时摄影
```

**底部导航调整（已拍板 D1）**：当前底部导航为 5 个 Tab
`0=主页 1=微信 2=销售 3=管理 4=设置`。「监控」插到主页之后成为第 2 位，其余顺延：

| 新索引 | Tab | 原索引 |
|---|---|---|
| 0 | 主页 | 0 |
| **1** | **监控** | **新增** |
| 2 | 微信 | 1 |
| 3 | 销售 | 2 |
| 4 | 管理 | 3 |
| 5 | 设置 | 4 |

**改造影响面**（`MainScreen.kt`）：
- `BridgeBottomBar.bottomTabs` 列表插入「监控」项（icon 建议 `Icons.Filled.Videocam`）。
- `when(selectedBottom)` 各分支索引顺延：微信 1→2、销售 2→3、管理 3→4、设置 4→5。
- `BackHandler` 中 `selectedBottom == 1/2/3` 分支同步顺延。
- `onDoubleTap` 微信双击判断 `idx == 1` → `idx == 2`。
- 微信未读角标 `index == 1` 判断 → `index == 2`。
- 沉浸式隐藏判断 `selectedBottom == 1/2` → `2/3`。
- 通知跳转 `selectedBottom = 1` → `2`；退出微信回主页 `selectedBottom = 0` 不变。

> ⚠️ 6 个底部 Tab 在手机底栏会偏挤，图标 22dp + 文字 10sp 需确认不重叠；必要时文字缩至 9sp。

### 4.1 实时预览（核心，最复杂）

**数据链路**（复用参考项目 API，零改服务端）：
- 摄像头清单：`GET /api/live/cameras` → `[{camera_id, nick}]`
- 静态快照：`GET /api/live/snapshot/{id}?quality=sub|main`（JPEG，抓帧即断，约 200KB/帧）
- 实时流：`GET /api/live/avstream/{id}?quality=sub|main&conn=xxx`（**fMP4 音视频流，H.264 画面 + AAC 声音，已拍板 D2 采用**）

**⚠️ 关键澄清（快照刷新机制）**：参考项目的快照是**「按需抓帧」而非「自动轮询」**——服务端没有定时刷新，刷新完全由客户端驱动。故 APP 原生设计需自实现三级刷新：

| 刷新粒度 | 交互 | 实现 |
|---|---|---|
| **单路刷新** | 预览卡片右上角「刷新」小按钮，只重抓该路一帧 | 单个 `/api/live/snapshot/{id}` 请求，回填该卡片 |
| **全部刷新** | 页面顶栏「刷新」按钮 / 下拉刷新，遍历在线摄像头并发重抓 | 并发抓取所有 camera_id，逐张回填 |
| **自动轮询（可选）** | 定时器 N 秒自动重抓（默认 10s），设置页可开关 | 定时器 + 复用单帧接口，省流模式默认关 |

**原生实现要点**：
- **音视频流（已拍板 D2）**：直接引入 **AndroidX Media3 ExoPlayer** 播放 fMP4 音视频流。相比 MJPEG（纯画面、无声音、需自写 SOI/EOI 解码器），ExoPlayer 原生支持 HLS/fMP4/HTTP 流、自带缓冲/重连/硬解，**是带声音的唯一正确路线**。
  - 依赖：`androidx.media3:media3-exoplayer` + `media3-exoplayer-hls` + `media3-ui`（需在 `gradle/libs.versions.toml` 新增，版本建议 1.4.x，与 compileSdk 36 兼容）。
  - 播放 URL：`/api/live/avstream/{id}?quality=sub&conn=<租约ID>`，`conn` 用于服务端心跳续租回收。
- **双模式带宽治理**（对齐 Web 端 + 大华范式）：
  - 默认「快照模式」：卡片墙显示静态帧（带单路/全部刷新），几乎零持续带宽；
  - 「实时模式」：点某一路进全屏，ExoPlayer 拉 fMP4 音视频流（有声音），单路持续。
  - 不做「多路同时实时」——卡片墙始终用快照，实时只发生在全屏单路，控住带宽/发热。
- **心跳续租**：`GET /api/live/heartbeat?conn=xxx` 每 2s 一次，离开页面/退出全屏停止（服务端 10s 无心跳回收 ffmpeg）。**必做**，否则服务端泄漏 ffmpeg 进程。
- **全屏**：点卡片 → 全屏音视频直播 + 流畅(子码流)/高清(主码流)切换 + 音量（因为有声音）。
- **鉴权**：`HUB_API_TOKEN` 通过 `X-API-Token` 头或 `?token=` 参数（媒体流 URL 用 query）。

**风险**：fMP4 子码流有声音后带宽略高于 MJPEG（音频 +32k AAC 可忽略），单路全屏可控；卡片墙快照模式默认省流。

### 4.2 事件

**数据链路**：`GET /api/events?level=&page=&page_size=` → 事件列表（含 `snapshot_exists`、`segment_name`、`camera_id`、`level`、`event_time`）。
快照：`GET /api/snapshot?path=xxx`。关联录像点播：`/api/video/by_segment?camera_id=&name=`。

**多节点**（已拍板 D3）：跨节点聚合走 `GET /api/hub/events?level=&page=&page_size=`（条目附 `node`/`node_nick`）。

**原生实现要点**：
- **列表**：按时间倒序，每条 = 事件快照缩略图 + 类型徽标（👤人形 / 🚶普通运动）+ 时间 + 摄像头名 + 节点名（聚合视图）。
- **筛选**：顶部 chip「全部 / 人形 / 普通运动」（对齐 Web level 筛选）。
- **详情**：点条目 → 大图快照 + 「看录像」按钮 → 跳全屏播放器点播关联段。
- **分页**：上拉加载更多（page 递增）。

### 4.3 云端

**数据链路**：`GET /api/cloud/list?path=&source=`（目录浏览，天翼优先百度兜底）。
点播：`/api/video/remote?path=&source=` 或流式 `/api/video/stream`。

**多节点**（已拍板 D3）：跨节点浏览走 `GET /api/hub/cloud/list?path=&source=`（共用网盘，任选在线节点代查，响应附 node/node_nick）。

**原生实现要点**：
- **目录树浏览器**：仿网盘 App 的层级浏览（`NVR备份/<camera_id>/<human|motion>/<YYYYMMDD>/<段名>.mp4`）。
- 面包屑路径导航 + 文件夹/文件图标区分 + 文件大小。
- 点视频文件 → 全屏播放器点播（`/api/video/stream` 流式，秒开；或 `/api/video/remote` 下载缓存后播）。
- **展示层映射**：camera_id → 昵称（南大门/北门）、human/motion → 中文、日期目录 → 友好日期（对齐 Web「昵称映射」做法）。

### 4.4 延时摄影

**数据链路**：`GET /api/timelapse/list` → `[{name(YYYYMMDD.mp4), size_mb, camera_id}]`。
点播：`/api/timelapse/play/{camera_id}/{name}`。

**多节点**（已拍板 D3）：跨节点聚合走 `GET /api/hub/timelapse/list`（条目附 node/node_nick）。

**原生实现要点**：
- **列表**：按日期倒序的卡片（日期 + 摄像头 + 节点 + 大小 + 缩略图可选）。
- 点播放 → 全屏播放器（首次下载缓存需数十秒，服务端已做缓存，二次秒开）。
- 说明文案：「每 30 分钟抓一帧，每天合成约 5 秒浓缩视频」。

## 五、多节点（hub 8200）的处理（已拍板 D3：多节点 + 聚合一起做）

NVR 有「单节点 8100」与「hub 8200 统一控制台」两种形态。APP 本期直接做全量多节点能力：

- **直连 hub 8200**：一个入口聚合所有节点。APP 访问 `http://86.74.128.68:8200`。
- **节点切换器**：顶栏下拉选择节点（「全部节点」+ 各节点）。
  - 选中某节点 → 媒体/列表请求经 `/<节点ID>/api/...` 代理前缀路由（实时预览/点播/快照走代理透传）。
  - 选中「全部节点」→ 列表页走 `/api/hub/events`、`/api/hub/timelapse/list`、`/api/hub/cloud/list` 聚合接口，条目带节点标识。
- **节点清单 + 健康状态**：`GET /api/hub/nodes` → `[{id, nick, online, summary}]`，切换器里显示在线状态点（绿/灰）。
- **实时预览的节点语义**：实时预览本质是「拉某节点某路摄像头的流」，故实时预览页也带节点切换器——选中「全部节点」时实时预览退化为「跨节点摄像头清单聚合」（二期可做），**一期实时预览默认落在某个具体节点**（因 `avstream`/`snapshot` 无跨节点聚合语义，只能按节点路由）。

> 若只部署单节点，可退化为直连 8100（`/api/...` 无前缀，无 hub 聚合）。

## 六、架构落点（Bridge 工程内）

### 6.1 新增模块

```
app/src/main/java/my/bridge/com/monitor/
├── MonitorPages.kt          # 监控页根（二级 Tab：预览/事件/云端/延时 + 节点切换器）
├── MonitorPrefs.kt          # 配置持久化（hub 地址、令牌、默认节点、自动轮询开关）
├── NvrApiClient.kt          # NVR HTTP API 封装（节点清单/事件/云端/延时/心跳/快照）
├── LiveView.kt              # 实时预览页（快照卡片墙 + 单路/全部刷新 + 全屏）
├── EventListView.kt         # 事件列表 + 筛选 + 详情（聚合/单节点）
├── CloudBrowserView.kt      # 云端目录树浏览器（跨节点）
├── TimelapseView.kt         # 延时摄影列表（聚合/单节点）
└── MonitorPlayer.kt         # 全屏播放器（ExoPlayer，云端/延时/事件录像/实时音视频共用）
```

### 6.2 复用 Bridge 既有能力

| 能力 | 复用点 |
|------|--------|
| HTTP 客户端 | 复用 OkHttp（新建独立实例，避免与主 WS 心跳耦合） |
| 令牌/地址配置 | 复用 `ServerAddress` 单框带协议模式 + SharedPreferences |
| 组网可达性 | 依赖现有 VNT 2.0 组网（无需新做） |
| 沉浸式导航/返回梯子 | 复用微信/销售/极空页同款「返回键逐级」范式 |

### 6.3 与服务端的关系

**零服务端改动**——全部消费 NVR 既有 REST API。唯一需要的是：
1. 确认 hub/节点的 `API_TOKEN` / `HUB_API_TOKEN`（APP 配置里填）；
2. 摄像头/节点昵称映射（可从 `/api/status` 拉 `cam_nicks` / `node_nick`，或 APP 侧写死）。

## 九、决策点结论（已拍板）

| # | 决策 | 结论 |
|---|------|------|
