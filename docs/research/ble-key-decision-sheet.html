先看这条：你的 B8 策略会让"车钥匙"在最常见的场景失效

你的策略是「前台播 / 连上极空播 / 两者都不满足后再宽限 5 分钟停」。失效场景是这样的：

  • 早上从屋里走到三轮车旁，手机在裤兜里，App 在后台，极空保护板还没连上（极空的 autoConnect 是挂起监听，发现保护板约需 30 秒）。
  • 此刻三个条件都不满足 → 不广播 → 对端扫不到 → 不通电。
  • 你得站在车边等：~30 秒等极空连上 + 2~3 秒等对端判近，最坏半分钟才通电。

也就是说，这个策略把"钥匙"变成了"要等半分钟的东西"。这不是实现细节，是策略本身的性质。B8 我给了 4 个候选，其中 ② 和 ④ 是为了既省电又不牺牲可用性。

第二条：版本号 versionCode 不能降

当前是 versionName 0.2.182 / versionCode 382（历史上一直是 200+补丁号）。你若用 v0.3.001 推 code 301，安装器会按"降级"直接拒绝，update.json 的包也装不上。F5 里给了两个不降的写法。

第三条：原文的字节账算错了，这条不能照抄

原文说「company 2 + payload 23，共 25 字节」。实际一个 AD 单元是 1(len)+1(type)+2(company)+23(data)=27，系统还会再塞 Flags 3 字节 → 30 / 上限 31。

若 Android 再自动加一个 TxPower 字段（3 字节）= 33 → 超限 → startAdvertising 直接报 ADVERTISE_FAILED_DATA_TOO_LARGE，广播永远起不来。所以 A7 那两行必须显式写死，不是可选项。
