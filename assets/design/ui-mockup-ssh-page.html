Bridge · SSH 服务 UI 原型 v1

客户端内嵌 sshd —— 设置 → 连接页分区 + SSH 服务状态页
方案 A：Apache MINA SSHD 纯 Java 内嵌 + sshd-mina 传输层 端口 8022（可配） 全盘：MANAGE_EXTERNAL_STORAGE（已拍板） 完整 sh（已拍板） 命令 ssh_start / ssh_stop / ssh_status
交互要点：
① 设置 → 连接页新增「SSH 服务」分区——开关 + 状态徽章 + 进入状态页（参照「智能控制」分区样式）。
② 状态页（运行中）——连接信息卡（地址/端口/用户名）、访问密码卡（首启随机生成、可隐藏、可随时修改并持久化）、主机密钥指纹卡（首次连接信任凭据）、存储授权卡、活动会话列表、停止按钮（红=点击后动作，与智能控制按钮语义一致）。
③ 首启引导——hostkey 首次生成提示 + 随机密码展示 + 「所有文件访问」授权引导卡（未授权回退 /sdcard/bridge 基础档）。
④ 修改密码弹窗——支持「随机生成」与自定义，保存即持久化、立即生效（无需重启服务）。
⑤ 错误态——端口占用等启动失败给出明确 UI 错误而非静默。

实现对照（Compose）与已拍板决策：
  • 设置分区参照「智能控制」RelaySwitchPages 的卡片 + Switch 样式；状态页为独立页（ui/SshPages.kt），开关颜色语义 = 按钮颜色表示点击后动作（停止→红、开启→绿，与智能控制一致）。
  • 已拍板：端口 8022（Prefs 可改）；首启随机密码展示于状态页、可随时修改且持久化；P0 直接申请全盘（MANAGE_EXTERNAL_STORAGE，未授权回退基础档）；P0 开放完整 sh；命令 ssh_start / ssh_stop / ssh_status（v0.2.33 状态联动全套：后台 unknown 一律禁用下发、强制下发=勾选+二次确认；设备端幂等守卫前置）。
  • 安全栈全程无证书：SSH 加密来自协议自身密钥协商；hostkey 为服务端自生成密钥对（非 TLS 证书），指纹即「首次连接信任」凭据。
  • 前台服务 = specialUse（照 VntVpnService 模式，crash-ledger §5 清单逐条打勾）；通知含 IP:端口 与停止 action。
