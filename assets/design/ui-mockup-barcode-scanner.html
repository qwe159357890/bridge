Bridge · 快递扫码 UI 原型 v1

扫码快递单号 → 批量上报 Bridge 服务端 → 管理后台实时看板/CSV
主页新增第 4 个 Tab「快递扫码」（智能控制之后） CameraX + ML Kit（多帧一致性投票） 协议照 putScanSessions/ACK 语义自定（REST 批量 + 离线对账） 包名 scanner/（区分 switch/ relay/）
功能范围：
① 扫码主界面 —— 相机取景区（四角框 + 命中高亮）+ 模式切换（单次/连续/手动）+ 连接状态胶囊 + 当前会话卡（名称/计数/上报状态）。
② 扫描反馈 —— 成功震动+提示音（可设置）、绿色确认卡「连续 2 帧一致」；重复单号按去重策略静默忽略或 toast 提示。
③ 会话记录 —— 单号列表（格式标签/时间/上报状态点），导出 CSV、清空；每条记录=一次扫码。
④ 设置弹窗 —— 服务器地址、扫描模式、去重策略四选一、格式白名单（快递场景默认 CODE_128/CODE_39/QR）、提示音/震动/手电筒。
通信模型：页面生命周期照智能控制——进入 start()、离开 stop()（相机 unbind + 上传停止）；扫码结果本地队列暂存，联网后按会话批量上报，putScanAck 语义确认，断网不丢。
会话按自然日管理（已拍板）：每天一个会话、自动按日期命名（如「10月30日 出库单」），同日不支持多会话；同日再开 = 设置项「自动进入今日会话」决定直接进列表或停在选择页；跨天第一次打开 = 提示卡「今天还没有今日出库单」→「创建今日出库单」/「查看历史」。

实现要点（对应调研文档 §6）：
  • 准确率核心：多帧一致性投票（同值连续 ≥2 帧才确认）+ 格式白名单 + 正则 filter 校验 + EAN/UPC 校验位自验 —— 这是相对参考项目（老 ZXing 一帧一拍）的关键增强。
  • 速度：CameraX 1280×720 + STRATEGY_KEEP_ONLY_LATEST + YUV_420_888 直通 ML Kit + 连续自动对焦 + 支持设备上 ML Kit 自动变焦。
  • 交互语义照参考项目：单次/连续/手动三模式、重复码四策略（默认相邻去重）、mixed_continue 的「继续添加？」倒计时弹窗、成功展示 800ms。
  • 生命周期照智能控制纪律：进入 start()（绑相机 + 启上传器），onDispose stop()（unbind + 清 handler）；状态用不可变快照参数化，杜绝 LazyVerticalGrid 漏刷。
  • 离线不丢：本地队列 + 会话级批量上报 + ACK 确认 + 重连对账（照 unsynced deleted/restored 设计）。
  • 会话按自然日管理：每天一个会话、自动按日期命名；同日打开由设置项「自动进入今日会话」决定行为；跨天第一次打开给提示卡「创建今日出库单 / 查看历史」；昨日未上报记录照旧自动补传，不合并（见调研文档 §5.5）。
